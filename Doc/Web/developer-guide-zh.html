DuCom 开发者文档

理解工程边界、接收管线、构建测试、性能约束和 Release 流程。

开发环境工程结构架构并发规范测试本地化贡献发布

开发环境与构建

Windows 10/11、.NET 10 SDK、Git，推荐 Visual Studio 的“.NET 桌面开发”工作负载。

git clone https://github.com/adu9527/DuCom.git
cd DuCom\DuCom
dotnet restore
dotnet build
dotnet run --project src\DuCom\DuCom.csproj
dotnet test DuCom.slnx

工程结构

Doc/                       对外中英文文档
DuCom/src/DuCom/           WPF 应用
DuCom/src/DuCom.Core/      无 UI 依赖的核心逻辑
DuCom/tests/               xUnit 测试
DuCom/tools/               负载工具
DuCom/benchmarks/          性能基准
DuCom/docs/                ADR 与内部验证资料

Core 保持零 WPF 依赖；协议、解析、存储和状态机优先放入 Core。

核心架构

SerialPort callback
 → 有界接收管线
 → STR / HEX / ANSI 增量格式化
 → Session sink
    ├─ 异步文件日志
    └─ 预算化显示存储
       → UI 按渲染节奏读取快照
  • 回调只复制和入队，不解析、不写盘、不调 Dispatcher。
  • 日志写入独立于 UI 跟随和显示裁剪。
  • 打开、关闭和异常断开显式串行化。
  • 命令组在异步发送上增加多目标、延时、返回检查与循环。

性能与并发规范

  • 禁止阻塞 SerialPort.DataReceived。
  • UI 批量、限频刷新；搜索、导出和磁盘写入后台执行。
  • 热路径避免逐字节对象分配。
  • 后台循环支持取消和幂等停止。
  • 用户正则必须设置超时。
  • 明确区分显示裁剪和真实接收丢失。

测试策略

自动化

编码、解析、搜索、正则超时、生命周期、存储预算、迁移、管线和多目标命令。

硬件与负载

真实 USB 串口、热插拔、端口占用、错误帧、高波特率长跑和确定性完整性对比。

dotnet build DuCom.slnx --configuration Release
dotnet test DuCom.slnx --configuration Release

本地化与持久化

可见文本放在 Resources/Languages/zh-CN.xaml 和 en-US.xaml，资源键保持一致。配置采用原子写入和向后兼容；Telnet 明文密码仅保存在运行内存。

贡献流程

  1. 从 test 分支创建功能分支。
  2. 确定 Core/WPF 边界并先补纯逻辑测试。
  3. 实现取消、错误和持久化语义。
  4. 同步中英文资源和文档。
  5. 通过 Debug/Release 构建、测试和必要手测。
  6. 向 test 提交 PR，并附测试证据与界面截图。

不要提交 bin、obj、日志、数据库、个人配置和发布 EXE。

Release 发布

面向用户发布当前实测约 78 MB 的自包含单文件 EXE（不同版本可能略有浮动），下载后直接双击，无需安装 .NET。
配置值
ConfigurationRelease
Runtimewin-x64
DeploymentSelf-contained
Single fileEnabled
dotnet publish src\DuCom\DuCom.csproj `
  -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true

发布前检查版本、关于页日期、文档、README、Release Notes、安全扫描和干净机器启动。产物上传 GitHub Release，不提交仓库。
