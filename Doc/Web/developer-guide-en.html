Environment and Build

Windows 10/11, .NET 10 SDK, Git, and preferably Visual Studio with the .NET desktop development workload.

git clone https://github.com/adu9527/DuCom.git
cd DuCom\DuCom
dotnet restore
dotnet build
dotnet run --project src\DuCom\DuCom.csproj
dotnet test DuCom.slnx

Project Layout

Doc/                       public bilingual docs
DuCom/src/DuCom/           WPF application
DuCom/src/DuCom.Core/      UI-independent core
DuCom/tests/               xUnit tests
DuCom/tools/               load tools
DuCom/benchmarks/          performance benchmarks
DuCom/docs/                ADRs and internal evidence

Core remains free of WPF dependencies. Protocol, parsing, storage, and state-machine behavior should live there.

Core Architecture

SerialPort callback
 → bounded receive pipeline
 → STR / HEX / ANSI incremental formatting
 → session sink
    ├─ asynchronous file log
    └─ budgeted display store
       → UI reads snapshots on render cadence
  • The callback only copies/enqueues; it never parses, writes files, or dispatches UI work.
  • File logging is independent from follow and display trimming.
  • Open, close, and disconnect transitions are serialized.
  • Command groups add multiple targets, delays, result checks, and loops to asynchronous sending.

Performance and Concurrency

  • Never block SerialPort.DataReceived.
  • Batch/rate-limit UI updates; move search, export, and file writes off the UI thread.
  • Avoid per-byte allocations in hot paths.
  • Background loops support cancellation and idempotent stop.
  • User-controlled regex has a timeout.
  • Distinguish display trimming from true reception loss.

Testing

Automated

Encoding, parsing, search, regex timeout, lifecycle, storage budgets, migration, pipeline, and multi-target commands.

Hardware and Load

Real adapters, hot-plug, occupied ports, serial errors, high-baud endurance, and deterministic completeness comparison.

dotnet build DuCom.slnx --configuration Release
dotnet test DuCom.slnx --configuration Release

Localization and Persistence

Visible text belongs in Resources/Languages/zh-CN.xaml and en-US.xaml with matching keys. Configuration writes are atomic and backward compatible. The Telnet plaintext password is runtime-only.

Contribution Workflow

  1. Create a feature branch from test.
  2. Choose the Core/WPF boundary and add pure-logic tests first.
  3. Implement explicit cancellation, errors, and persistence.
  4. Synchronize bilingual resources and documentation.
  5. Pass Debug/Release builds, tests, and required manual checks.
  6. Open a PR against test with evidence and screenshots.

Do not commit bin, obj, logs, databases, personal settings, or release executables.

Release Publishing

Users receive a self-contained single EXE currently measured at approximately 78 MB (the size may vary slightly between versions) and can run it without installing .NET.
SettingValue
ConfigurationRelease
Runtimewin-x64
DeploymentSelf-contained
Single fileEnabled
dotnet publish src\DuCom\DuCom.csproj `
  -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true

Before publishing, verify version metadata, About date, documentation, README, release notes, malware scan results, and startup on a clean machine. Upload the output to GitHub Releases; do not commit it.
